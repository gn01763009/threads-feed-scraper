# Threadsスクレイパー — 投稿・プロフィール・ハッシュタグ・キーワード検索

Meta Threads用の統合スクレイパー。**ユーザープロフィール**、**ハッシュタグ**、**キーワード検索**、**単一投稿と返信**、**カスタムフィード**の5モードを1つのActorでカバー。ログイン不要、APIトークン不要、一度に最大100件のユーザー名やキーワードを一括貼り付け可能、開始手数料なしで**1件$0.005**の固定料金。マーケター、リサーチャー、SaaS開発者、ソーシャルリスニングチーム向けに、Metaの公式APIを構築せずにThreadsデータを取得したい方に最適です。

---

## このスクレイパーが取得するデータ

各投稿について:

- `postId`、`postUrl`、`content`、`publishedAt`、`publishedAtISO`
- `mediaType`(`text` / `photo` / `video` / `carousel`)と`mediaUrls[]`
- エンゲージメント:`likeCount`、`replyCount`、`repostCount`、`shareCount`、`viewCount`、`quoteCount`
- `sourceType`(どのモードで取得したか)と`sourceQuery`(正確なユーザー名 / キーワード / URL)
- `scrapedAt`タイムスタンプ
- `threadParts[]` — 複数セグメントのスレッド投稿は自動的にマージされ、各セグメントが保持されます

投稿者について:

- `author`ハンドル

返信について(`post`モードのみ):

- `replies[]` — `author`、`content`、`publishedAt`、`likeCount`付きの主要返信を最大20件

データセットのフィールドキーはすべてのロケールで英語 — 下流のツールチェーンはポータブルなまま。

---

## 5つのモード、1つのActor

| モード | 機能 | 入力フィールド |
|--------|------|----------------|
| 👤 **User** | ユーザープロフィールの全投稿を取得 | `usernames[]` |
| 🏷️ **Hashtag** | ハッシュタグ / トピックページを取得 | `keywords[]` |
| 🔎 **Search** | キーワード検索(トップ / 最新でソート) | `keywords[]` + `searchSort` |
| 💬 **Post** | 単一投稿と最大20件の主要返信 | `postUrls[]` |
| 📰 **Feed** | 任意のThreadsカスタムフィードURL | `feedUrls[]` |

実行ごとに**Mode**ドロップダウンから1つのモードを選択します。競合スクレイパーはこれらを4〜5個の別々のActorに分割していますが、このスクレイパーは1つのコードベースにまとめているため、インテグレーションがシンプルなままです。

## 入力項目

| フィールド | 型 | 必須 | デフォルト | 説明 |
|-----------|----|:----:|:---------:|------|
| `mode` | enum | 推奨 | `user` | `user`、`hashtag`、`search`、`post`、`feed`のいずれか。省略時は入力されたフィールドから自動判定。 |
| `usernames` | string[] | `user`モード時 | — | プレーンなユーザー名。`@`やURLは不要。最大**100**件。 |
| `bulkUsernames` | string | 任意 | — | テキストエリア — 1行に1ユーザー名を貼り付け(スプレッドシートの列を直接コピー可能)。`usernames`にマージされます。 |
| `keywords` | string[] | `hashtag` / `search`時 | — | キーワードまたはハッシュタグ(先頭の`#`は省略可)。最大**100**件。 |
| `bulkKeywords` | string | 任意 | — | キーワード用のテキストエリア貼り付け。`keywords`にマージされます。 |
| `postUrls` | string[] | `post`モード時 | — | 完全なThreads投稿URL — 返信は自動で取得されます。 |
| `feedUrls` | string[] | `feed`モード時 | — | ThreadsカスタムフィードURL。 |
| `searchSort` | enum | 任意 | `top` | `top`または`recent`。`search`モードのみに適用。 |
| `dateFrom` | string | 任意 | — | `YYYY-MM-DD` **または**相対:`7 days`、`1 month`、`2 weeks`、`1 year`。 |
| `dateTo` | string | 任意 | — | `dateFrom`と同じ形式。 |
| `maxPosts` | integer | 任意 | `50` | ソースあたりの最大投稿数(1〜500)。スクロールは自動管理。 |

## 使用例

**👤 3つのユーザープロフィールを取得**

```json
{
  "mode": "user",
  "usernames": ["zuck", "mosseri", "finkd"],
  "maxPosts": 50
}
```

**🏷️ 直近1ヶ月のハッシュタグを取得**

```json
{
  "mode": "hashtag",
  "keywords": ["#AIニュース"],
  "dateFrom": "1 month",
  "maxPosts": 200
}
```

**🔎 キーワード検索、直近7日間の最新投稿**

```json
{
  "mode": "search",
  "keywords": ["LLMエージェント", "バイブコーディング"],
  "searchSort": "recent",
  "dateFrom": "7 days",
  "maxPosts": 100
}
```

**💬 単一投稿 + 主要返信**

```json
{
  "mode": "post",
  "postUrls": ["https://www.threads.com/@zuck/post/ABC123"]
}
```

**📋 一括貼り付け — スプレッドシートから80個のKOLアカウント**

Googleスプレッドシート / Excelから列を直接コピーして`bulkUsernames`に貼り付けるだけ — 「追加」を80回クリックする必要はありません。

**Console形式:1行に1ユーザー名、改行で区切ります — 引用符やカンマは不要です。** こんな感じ:

```
zuck
mosseri
finkd
threadsapp
taylornikolai
```

Consoleではなくapi呼び出しの場合、`bulkUsernames`は`\n`を改行区切りとする単一の文字列です:

```json
{
  "mode": "user",
  "bulkUsernames": "zuck\nmosseri\nfinkd\nthreadsapp\ntaylornikolai",
  "maxPosts": 20
}
```

## 注意事項と制約

- **`maxPosts`は上限であり保証ではありません。** 非アクティブなプロフィールやニッチなハッシュタグでは返される投稿数が少なくなる場合があります。5回連続で新しい投稿が取れなかった時点で早期終了します。
- **相対日付は実行時に評価されます。** 今日の`"7 days"`と明日の`"7 days"`は異なる絶対日付になります — 「直近1週間」を常に取得するスケジュール実行に便利です。
- **エンゲージメント数は概算の場合があります。** Threadsは大きな数値を省略表記します(例:`12.5K`)。Actorはこれを整数に正規化するため、`12500`は変換後の値であり正確なカウントではありません。
- **返信は`post`モードでのみ取得されます。** 各投稿あたり最大20件の主要返信に制限されています。
- **ログイン不要 = 公開データのみ。** 非公開アカウントやフォロワー限定コンテンツにはアクセスできません。
- **スレッドチェーンは自動的にマージされます。** 複数セグメントの投稿(`1/`、`2/`、`3/`)は`threadParts[]`を介して単一のレコードに結合されます。

## FAQ

**Q: ユーザー名はどう渡しますか?`@`あり / なし、完全なURL?**
プレーンが標準です:`zuck`であり、`@zuck`や`https://www.threads.com/@zuck`ではありません。先頭の`@`は自動的に削除され、v0.3のレガシー`profileUrls`フィールドは自動マイグレーションされるため、既存のAPIインテグレーションは壊れません。

**Q: 部分的な結果しか取れません — `maxPosts`より少ない投稿数です。なぜ?**
プロフィールに本当に投稿が少ないか、ハッシュタグがニッチか、Threadsのフィードが繰り返しスクロール後に新しいアイテムを返さなくなったかのいずれかです。実行ログの`totalItems`を確認してください — それが実際のカウントです。

**Q: 一部のフィールドが`null`や`0`です。バグですか?**
Threadsはエンゲージメント数を遅延レンダリングします。特に表示回数は、十分な公開リーチを持つアカウントでのみ表示されます。引用数は投稿タイプに依存します。欠損フィールドはThreads側のデータギャップであり、Actor側のサイレント失敗ではありません。

**Q: `dateFrom` / `dateTo`は`user`や`post`モードにも適用されますか?**
日付フィルターはすべてのモードで動作しますが、`search`、`hashtag`、`user`、`feed`でのみ意味を持ちます — `post`モードは日付に関係なく指定されたURLを取得します。`"1 month"`のような相対式はフィルタリング前に絶対`YYYY-MM-DD`に解決されます。

**Q: どの出力形式がサポートされていますか?**
JSON、CSV、Excel、XML、HTMLテーブル — 標準のApifyデータセットエクスポートです。Apify Console、データセットAPI、またはApifyクライアントライブラリ(Python、JavaScript)から利用できます。Zapier、Make、n8n、Google Sheetsとの連携も可能です。

## 代替案:Threads公式API

Metaは[Threads公式API](https://developers.facebook.com/docs/threads)を公開していますが、公開データの用途には厳しい制約があります:

- 自分が所有する、またはアクセス権を付与されたアカウントからのみデータを読み取れます — 競合監視、トレンド調査、ハッシュタグスクレイピングはできません
- OAuth設定、パブリッシングツールのアプリレビュー、Facebook Developerアカウントが必要です
- レート制限とエンドポイントの対応範囲は、ログアウト状態のブラウザで見えるものよりも狭くなっています

市場調査、ソーシャルリスニング、トレンド分析、公開Threadsデータの競合インテリジェンスには、このActorがよりシンプルな道です。投稿、自分のアカウントの管理、承認されたアカウントでの自動化構築にはMetaの公式APIを使用してください。
